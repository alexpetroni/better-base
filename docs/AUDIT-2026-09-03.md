Six parallel area reviews (shop/Stripe/shipping, invoicing/e-Factura, chat/nurture/email/CRM,
media/content/quiz, auth/admin/GDPR/frontend, ops/CI/migrations) reading the code under
`apps/web/`, plus independent verification of the gate and of every P0 by hand. The
2026-07-09 audit and its eight FIX rounds were taken as the baseline: nothing from it is
repeated unless it regressed. Every item cites `file:line` relative to `apps/web/`.
Nothing here was auto-fixed.

**Independently verified on this machine:** `pnpm lint` clean, `pnpm check` clean
(3449 files, 0 errors), `pnpm test:unit` 770 passed / 4 skipped (89 files; the 4 skips are
the Neon-proxy parity cases that only run under `pnpm test:neon`), formcomp 27 passed.
The Svelte autofixer reports no issues in the core components. The P0 admin-guard bypass
below was reproduced live against `pnpm preview` of the current build.

**Overall:** the record layer is unusually good — transactional order creation, an
exactly-once event ledger, gapless invoice numbering under a row lock, append-only fiscal
tables enforced by triggers, atomic rate limits, a nurture queue claimed with
`FOR UPDATE SKIP LOCKED`, and a boot/env discipline most teams never reach. The risk has
moved to the seams the launch batch created after the last audit: what happens *after* the
first payment (refunds, async payments, couriers), the fiscal-content layer around a sound
ledger, the mail/queue edge cases, and the pipeline that will carry this 64-commit branch
into production for the first time. Plus one real authorization hole.

## P0 — do not deploy before these

### 1. Admin guard bypass via percent-encoded path (verified live)

`src/hooks.server.ts:54-73`, `src/routes/admin/(shell)/subscribers/export.csv/+server.ts:6-8`,
every `+page.server.ts` action under `src/routes/admin/(shell)/**`.

The guard keys on `deLocalizeUrl(event.url).pathname`, which is not percent-decoded.
SvelteKit decodes the path before matching routes (`@sveltejs/kit/src/runtime/server/respond.js:268`).
So `/%61dmin/…` reaches the `/admin/…` route with `locals.user = null` and the guard never runs.
Page GETs are saved by the shell layout's redirect, but `+server.ts` endpoints have no check of
their own, and **form actions run before any layout load**.

Reproduced against the built app:

```
GET /admin/subscribers/export.csv      → 303 → /admin/login
GET /%61dmin/subscribers/export.csv    → 200 text/csv, attachment, full subscriber table
POST /%61dmin/media?/delete            → 303 (action executed; plain path → 303 to login)
```

Anonymous subscriber-list export; unauthenticated `?/save`, `?/publish`, `?/delete` (incl. the
S3 object) on pages, articles, products, media. `settings?/save` only survives because
`locals.user!.id` throws (500, not 403).

**Fix (two layers):**
1. Key the guard on the resolved route id, which SvelteKit sets before `handle`:
   ```ts
   const routePath = (id: string | null) => (id ?? '').replace(/\/\([^/]+\)/g, '');
   const pathname = routePath(event.route.id); // '/admin/(shell)/settings' → '/admin/settings'
   ```
2. Defense in depth: `requireStaff(locals)` / `requireAdmin(locals)` helpers in `$lib/server/forms.ts`,
   called first in every admin action and every `+server.ts` under `/admin` and `/api/shipments`.
   Replace the `locals.user!` assertions. Add a hook-level spec that requests
   `/%61dmin/subscribers/export.csv` and `POST /%61dmin/pages/x?/save` and expects 303/401.

### 2. A partial refund is processed as a full refund

`src/lib/modules/shop/webhook.ts:340-405`, `src/lib/modules/invoice/service.ts:257-322`,
`src/lib/modules/invoice/schema.ts:140` (`invoices_storno_of_uq`), `shipment-service.ts:318-357`.

`charge.refunded` fires for partial refunds too. The handler never reads `charge.amount_refunded`
(grep: nothing in `src/` does). It sets `orders.status='refunded'`, issues a storno of the
**whole** invoice, cancels fulfillment or the AWB. The oversell comment at `webhook.ts:231-233`
recommends "partial refund" as the operator remedy — i.e. the documented workflow produces a
fiscally false storno and cancels a shipment for goods the customer keeps. Second partial refund →
`storno-failed` noise. The one-storno-per-invoice unique index makes the correct sequence
structurally impossible. Both refund fixtures omit `amount`/`amount_refunded`, so no test covers it.

**Fix:** branch on `charge.amount_refunded < charge.amount`. Partial → append `refund-partial`
(amount) to the trail, keep `status='paid'`, do not storno, do not touch fulfillment; add
`orders.refunded_cents` and an admin "storno parțial" action that issues a storno whose gross equals
the refunded amount (VAT extracted at the original line rate). Replace the unique index with a
check Σ stornos ≤ original. Integration test for the partial case.

### 3. A refund that arrives before its order is lost; the order is then created paid and shipped

`webhook.ts:351-361, 393-394`, `src/routes/api/stripe/webhook/+server.ts:48`,
`src/lib/server/event-ledger/core.ts:71-81`.

An unmatched refund returns `refund-unmatched` *inside* `runOnce`: the ledger row commits and the
route answers 200, so Stripe never redelivers. If the `checkout.session.completed` arrives later
(rotated webhook secret, bad deploy, retry backlog in arbitrary order) the order is created `paid`,
invoiced, emailed, enrolled in nurture and queued for shipping — for money already returned.

**Fix:** persist unmatched refunds (`pending_refunds(payment_intent, charge_id, amount)`) and
reconcile in `createOrderFromSession`: a pending refund for the intent → order created `refunded`
(+ invoice + storno), no email, no nurture. Alternatively throw → 5xx → Stripe retries for 3 days.
Test both orderings.

### 4. Fiscal documents live in the publicly bound media bucket

`src/lib/modules/invoice/documents.ts:22` (`invoices/` prefix in `S3_BUCKET`),
`src/lib/modules/media/storage.ts:148-165` (`s3:GetObject` on `bucket/*`), `DEPLOYMENT.md §5`
("bind the bucket to a public custom domain"), `modules/invoice/README.md:164-168` ("private").

Under `IMAGE_PROVIDER=cloudflare` (the default) the whole bucket is bound to a public custom domain;
R2 public access is not prefix-scoped. `https://media.<site>/invoices/<invoiceId>.pdf` then serves
name/address/email with no token, no expiry, edge-cached — while the app route enforces a 15-minute
HMAC. Only UUID entropy protects it; ids appear in success-page links and the admin.

**Fix:** a separate private bucket for fiscal documents (`S3_INVOICE_BUCKET`), or at minimum a
Cloudflare WAF rule blocking `/invoices/*` on the media hostname plus a `launch:check` probe that
`${MEDIA_PUBLIC_BASE_URL}/invoices/probe.txt` is not 200. Correct README/DEPLOYMENT.

### 5. The path to production has no gate and no ordering

`.github/workflows/migrate.yml:22-24`, `DEPLOYMENT.md:572-579`, `origin/main` at `2a0b878`
(64 commits behind; `.github/` does not exist on `main`).

The only workflow applies production DDL on every push to `main` — with no lint, check, test or build
in front of it; the project's own gate (`pnpm lint && pnpm check && pnpm test:unit`) lives only in the
phase-runner. The migrate job and Vercel's Git integration fire on the same push with nothing ordering
them; "the schema is current before Vercel promotes" is aspirational. New code on an old schema 500s
the checkout/webhook/admin until the job finishes; a failed migration (secret missing on first merge,
Neon hiccup, formcomp `prepare` failure) does not stop the deploy. Preview deployments may point at
production Neon.

**Fix:** one `ci.yml`: `gate` (postgres+minio services, lint/check/`db:migrate` on a fresh DB/
`drizzle-kit check`/test:unit/both builds/`launch:check --target=vercel` against a CI env) → `migrate`
(`needs: gate`, `environment: production`, existing concurrency group) → `deploy` (`vercel build --prod`
+ `vercel deploy --prebuilt --prod`; disable Vercel auto-production deploys). Belt-and-braces
regardless: Vercel Build Command `pnpm db:status && pnpm build` (`scripts/migrate-status.ts:52-55`
already exits non-zero while migrations are pending). Preview → Neon branches. Require `ci / gate`
in branch protection. Update `migrate-workflow.spec.ts:30-33`.

## P1 — fix before launch

### Shop & shipping

- **Pending orders are a dead end** (`webhook.ts:199, 237-247, 313, 412-424`; `stripe-gateway.ts:74-111`).
  `payment_status !== 'paid'` → `pending`, but stock is decremented and the confirmation email sent
  anyway; no handler for `checkout.session.async_payment_succeeded/failed`; `payment_method_types`
  not pinned, so any delayed method enabled in the Stripe dashboard silently hits this path.
  Fix: handle both async events (flip to paid → invoice → email; failed → restore stock, cancel), or
  pin `payment_method_types: ['card']`; never send "order confirmed" for `pending`.
- **Quantity is never compared with stock** (`checkout.ts:171`, `service.ts:44-46`, `cart.ts:22-25`).
  stock=1, qty=5 → charged for 5, `oversold`, remedy is P0 #2. Fix: `available` includes
  `qty <= stock`, expose `maxQty`, clamp in actions, refuse at checkout with "doar N bucăți".
- **Sameday adapter cannot produce a deliverable AWB** (`sameday-courier.ts:125-135`, `courier.ts:21`,
  `shipment-service.ts:109-116`). Recipient phone is required by Sameday and is sent as `''` (never
  collected: no `phone_number_collection`, `customer_details.phone` unread); county falls back to the
  city name; the 400 response body is discarded. Fix: enable phone collection, persist it into
  `shippingAddress`, typed `missing-recipient-data` error before calling the courier, include response
  body in errors, no city→county fallback. Endpoints/auth match the official SDK.
- **Shipment-sync starvation** (`shipment-service.ts:250-267`). A row whose `trackShipment` throws
  keeps its head-of-queue position; 25 poisoned AWBs stop every other shipment from ever reaching
  `delivered`; an auth failure fails all rows hourly with a `console.log`. Fix: bump `last_synced_at`
  (or `next_sync_at` + backoff + `error_count`) on error, abort on auth error, surface runs with errors.
- **Courier-cancelled AWB is a dead end** (`shipment-service.ts:94-96, 219-225, 285-301`): order stays
  `shipped`, out of the queue, and `createShipmentForOrder` returns the cancelled row so no replacement
  AWB is possible. Fix: `shipped → packed` edge for the sync actor, allow re-creation when the existing
  row is `cancelled` (partial unique index), `awb-cancelled-externally` event.
- **Status classification by substring** (`sameday-courier.ts:30-37`): `includes('livrat')` matches
  "nelivrat". Fix: classify on `statusId`, anchored negatives, warn on unknown text; capture real
  payloads as fixtures during the live-AWB launch step.

### Invoicing & e-Factura

- **One global VAT rate, no per-product rate, no effective dating** (`invoice/service.ts:162-176`,
  `settings/registry.ts:170-180`; no VAT column on `products`/`order_items`). RO has 21% standard /
  11% reduced since 2025-08-01; the repo's own fixture (chamomile tea) is invoiced at 21%. The rate is
  read at issuance, not at the chargeability date, so a retried invoice after a rate change gets the
  wrong rate. Fix: `products.vat_rate_bp` (nullable → fallback), snapshot onto `order_items` and
  `invoice_lines`; effective-dated standard-rate list selected by `order.createdAt`.
- **CUI is shape-only; issuer `RO` prefix not reconciled with `company.vatRegistered`**
  (`util/cui.ts:6`, `efactura.ts:221-238`, `legal.ts:33-36` — `displayCui` exists, unused by the
  invoice). Every spec fixture CUI fails the mod-11 checksum. Fix: `isValidCui()` in the buyer form and
  the setting validator; store `displayCui(cui, vatRegistered)` at snapshot; consistency rule in
  `missingIssuerSettings`.
- **The XML is not valid CIUS-RO for any Romanian address** (`efactura.ts:95-149, 216-243`;
  `README.md:151-156` calls it compliant). Missing `CountrySubentity` (acknowledged, but fatal by
  itself); `CityName` is `issuerPlace || issuerAddress` for the seller and `"<postal> <city>"` for the
  buyer; no `SECTORn` rule for București; `PostalZone` never emitted; buyer `PartyTaxScheme` emitted
  under category O (BR-O-2). Fix: structured address fields in the snapshot (+ `company.county/city/
  postalCode` settings; map Stripe `state` → ISO 3166-2:RO), emit `CountrySubentity`/`PostalZone`,
  suppress buyer VAT id under O, extend `validateEFacturaXml`, one golden fixture validated against
  ANAF's public validator.
- **SPV submission is mandatory (5 calendar days) but nothing tracks it** (`documents.ts:371-390`,
  `DEPLOYMENT.md:356-359` says "when required"). XML is rendered lazily on a customer GET. Fix:
  `invoice_submissions` table written at issuance, a cron that renders/submits/retries, an admin
  "de trimis la ANAF" filter; correct the docs.
- **Share capital missing** (Legea 31/1990 art. 74 for SRL/SA) — no setting, no snapshot column, not
  printed. Fix: `company.shareCapital`, launch-required, printed under Reg. Com.
- **B2B invoices carry the parcel address; B2C name is the parcel recipient** (`service.ts:118-129,
  213-218`, `checkout.ts:73-98`). Fix: company address in the B2B form and snapshot; prefer
  `customer_details.name` for consumers.

### Email, CRM & nurture

- **`email_log` treats `dryrun` and `sending` as final forever** (`email/service.ts:65-67, 123-129`;
  `nurture/drain.ts:166-191` counts `skipped` as `sent`). The documented dry-run soak burns every
  confirm/nurture key of that window: after `EMAIL_DRYRUN=false` the same key → `skipped`, the page
  says "sent", nothing goes out. A serverless kill between the `sending` claim and the transport
  leaves the row stuck and the drain marks it `sent`. Fix: reclaim `sending` after a staleness window,
  never treat `dryrun` as delivered when `dryRun === false` (or namespace dry-run keys), drain accepts
  `skipped` only when the log row is `sent`; `maxDuration` on the cron routes.
- **Unsubscribe is a GET side effect; no `List-Unsubscribe`** (`unsubscribe/[token]/+page.server.ts:6-13`,
  `resend.ts:29-42`). Mail scanners (Safe Links, Gmail, Apple MPP) fetch every link: the first nurture
  email unsubscribes such mailboxes. Fix: GET renders a POST form; RFC 8058 one-click POST handler;
  `List-Unsubscribe` + `List-Unsubscribe-Post` headers via Resend.
- **Unsubscribe keeps `confirmedAt`** (`crm/service.ts:114, 177-193`): anyone can re-opt-in a withdrawn
  address with no double opt-in, and the "already subscribed" response is a confirmed-status oracle.
  Fix: clear `confirmedAt` on withdrawal; same response for both outcomes.
- **Resend errors unclassified, no pacing, no bounce/complaint handling** (`resend.ts:45-47`,
  `drain.ts:166-184`). A 403/422 is retried 5× over ~21 h; 25 back-to-back sends vs Resend's 2 req/s.
  Fix: 429/5xx/network retryable, other 4xx park immediately; ~500 ms pacing; Resend webhook for
  `email.bounced`/`email.complained` → revoke + cancel nurture.

### Chat

- **History window can start with an assistant turn** (`chat/validate.ts:21-23`, `service.ts:126-131`).
  21 alternating rows, `slice(-20)` → first role `assistant` → Messages API 400 → generic error; every
  conversation fails deterministically at message 11 (masked by the mock in tests). Fix: drop leading
  non-user turns after capping; unit test on `capped[0].role`.
- **Provider call misconfigured for this workload** (`anthropic-provider.ts:45-58`, `service.ts:16`).
  On `claude-sonnet-5` omitting `thinking` runs adaptive thinking, whose tokens count against the
  1024-token `max_tokens`; `stop_reason` (`max_tokens`, `refusal`) is never read, so truncated/empty
  replies stream as normal `done` and are persisted; SDK errors (401/429/529) are swallowed with no log
  line. Fix: `thinking: { type: 'disabled' }` or `output_config: { effort: 'low' }` and a higher cap;
  read the final message and emit a distinct frame for `max_tokens`/`refusal`; log caught errors with
  class + status; stream-inactivity timeout. Also `timeoutMs`≈20 s/`maxRetries: 1` so the 180 s SDK
  budget fits `maxDuration = 60`; the panel should mark a bubble failed when the stream closes
  without `done`.
- **Cookieless POSTs insert session rows before the limiter; retention deletes in one statement**
  (`service.ts:83-113, 252-256`, `retention.ts:52-59`). Unbounded growth for an unauthenticated
  caller, then a daily `DELETE … RETURNING` that can never finish inside the 30 s
  `statement_timeout`, aborting every later pruner. Fix: consume the IP counter first; loop
  `DELETE … WHERE id IN (SELECT … LIMIT 5000)`; each pruner in its own try/catch; `ORDER BY … DESC
  LIMIT 20` for history (as `getChatHistory` already does).

### Media, content & blog

- **SVG "sanitize at rest" is bypassable; import/seed never sanitize** (`media/service.ts:115-126`,
  `storage.ts:29, 73-89`, `content/import.ts:68-72`, `db/seed.ts:127-128`, `svg.ts:52`). The presigned
  PUT stays valid 10 min after confirm and replaces the sanitized object and its `Content-Disposition`;
  `<style>` bodies (`@import url(…)`) pass through. Fix: presign into a quarantine key the public origin
  never serves; confirm *produces* the served object (`CopyObject` with `MetadataDirective: REPLACE`
  for rasters — also where `Cache-Control: immutable` belongs — sanitized `PutObject` for SVGs);
  sanitize in `ensureMedia` and the seed; drop `style` from the SVG allowlist.
- **`db:seed` / `content:init` overwrite live data despite "safe to re-run"** (`DEPLOYMENT.md:605`,
  `db/seed.ts:112, 150-161, 180`, `content/import.ts:189-268`). Re-running resets demo stock/prices/
  status, reverts admin edits, re-publishes. Fix: demo content create-only; import create-only by default
  with `--overwrite`; split `seed:base`/`seed:demo`; fix the doc.
- **Blog detail ignores pillar activity** (`blog/[slug]/+page.server.ts:12-13`, `blog/service.ts:168-181`;
  contrast quiz/product detail and `listPublished`). Untagged or de-pillared articles vanish from lists
  and sitemap but keep answering 200 with canonical + JSON-LD. Same for quiz result pages; quizzes are
  absent from the sitemap. Fix: `getBySlug(…, { pillarSlugs })` with the same `EXISTS` predicate.

### Auth, GDPR & frontend

- **No security headers / CSP** — verified none anywhere. Five `{@html}` sinks depend on one
  sanitize-html config; XSS on `/admin` can drive plain-POST actions (subscriber export, settings/IBAN
  change, AWB generation). Proposal that works with this app: static half in `kit.csp`
  (`script-src 'self' 'strict-dynamic'` nonces the bootstrap and trusts the DOM-injected analytics
  script; `style-src 'self' 'unsafe-inline'` for the inline theme/blurhash/score-bar styles), runtime
  half appended in a `handleSecurityHeaders` (`img-src` from `MEDIA_PUBLIC_BASE_URL`/`IMGPROXY_URL`
  + `data:`, `connect-src` analytics host + `S3_ENDPOINT` on admin only, `frame-src` the two iframe
  hosts, **`form-action 'self' https://checkout.stripe.com`** — Chrome enforces it on the 303 after
  the checkout form post — `frame-ancestors 'none'`), plus `nosniff`, `referrer-policy:
  strict-origin-when-cross-origin`, HSTS when `PUBLIC_SITE_URL` is https, `cache-control: no-store`
  on `/admin`. Roll out report-only first; validate on `pnpm preview` (SvelteKit strips
  `strict-dynamic` in dev).
- **hreflang `en` points at Romanian pages** (`(public)/+layout.svelte:28-35`, `paraglide/runtime.js:35-39`
  — strategy is `cookie, globalVariable, baseLocale`, no `url`; `e2e/frontend.e2e.ts:19` asserts the
  `/en/` alternate). `/en/x` renders `lang="ro"` Romanian content with canonical → `/x`: crawlable
  duplicate tree with conflicting signals. Content has no locale column; nav labels are hardcoded
  Romanian. Fix: either add `"url"` to the strategy and make canonical self-referential per locale,
  or emit alternates only when the site really has more than one locale (today: none).
- **GDPR erase misses mixed-case emails in `orders` and `email_log`** (`gdpr/erase.ts:68-72, 89-93`,
  `webhook.ts:192` stores `customer_details.email` verbatim). Fix: lowercase at write time; match with
  `lower(email)` + index; null `email_log.error`.
- **Editors see customer emails through the quiz editor and can rewrite legal pages**
  (`quizzes/[id]/+page.server.ts:25`, `guards.ts:4-10`). Fix: `latestResults` for editors; `pages`
  (or the legal slugs) admin-only.
- **Admin login for an account that can export all PII and change the invoice IBAN** has a
  per-IP-only lockout (`auth/rate-limit.ts:16-20`), no 2FA, 7-day rolling sessions, no login/export
  audit. Fix: second counter keyed by email; better-auth `twoFactor` (TOTP) required for `admin`
  (server-side `auth.api.verifyTOTP` in the form action — `/api/auth` need not be mounted);
  `session.expiresIn`≈12 h; log logins and exports.

### Ops & platform

- **The error log copies failed-query parameters (PII) to stderr** (`hooks.server.ts:86-98`,
  `log.ts:33-53`; drizzle's `DrizzleQueryError` message is `Failed query: <sql>\nparams: <params>`).
  Chat text, addresses, CUIs, emails, password hashes land in whatever log drain is attached. No request
  id, no sink seam. Fix: strip the `params:` block (and stack frames after it) in `formatServerError`;
  `x-vercel-id`-derived request id echoed as `x-request-id`; optional `ERROR_REPORT_URL` sink via
  `waitUntil`, registered in `env-matrix.ts`.
- **`launch:check` blesses a deploy whose shop is a mock** (`launch-check.ts:110-114`, `shop/server.ts:121-131`).
  An empty `STRIPE_SECRET_KEY` passes; the in-memory mock gateway then "takes" orders per function
  instance and no webhook ever arrives. Also accepts `--target=node` with `DB_DRIVER=neon` (one
  WebSocket for the whole server) and vercel without `neon`. Fix: three rules in `launchCheckProblems`.
- **No `maxDuration` on the three cron routes and the Stripe webhook** (only `api/chat` has one);
  the webhook renders the PDF, uploads and emails inside the invocation. The `*/15` and hourly crons
  require Vercel Pro (Hobby is daily) and the docs do not say so. Fix: `config = { maxDuration: 60 }`
  ×4; plan note in §12.
- **No backup/restore path** (`LAUNCH-CHECKLIST.md:203-204`; app token is Object Read & Write, R2 has
  no versioning; Neon PITR is a plan-sized rolling window). The fiscal PDFs/XMLs the law requires be
  retained have no off-provider copy. Fix: scheduled `pg_dump --format=custom` + `rclone sync` of the
  bucket to a second provider, a restore runbook, a lifecycle rule that never expires `invoices/`;
  turn the checklist box into a verified restore.
- **Neon path edges** (`db/client.ts:146-152, 58`, `health.ts:12`): the on-connect
  `SET statement_timeout` is `void`-ed — a rejection is an unhandled rejection that kills the
  instance; behind PgBouncer it is not a session guarantee; 5 s connect/health timeouts vs compute
  wake. Fix: `ALTER ROLE <app_role> SET statement_timeout = '30s'` (survives pooling), `.catch` + log on
  the SET, `DB_POOL_CONNECTION_TIMEOUT_MS=15000` on Vercel, run the documented real-Neon check before
  the first deploy.

## P2 — after launch, in this order of value

- **Nurture queue frozen at enrollment** (`drain.ts:71-100, 136-143, 166-212`, `nurture/service.ts:271-280`):
  pause→resume floods overdue steps in unspecified order; a config reseed shifts content under
  pending rows; parked sends close the enrollment as `completed` with no retry action. Cancel/replan
  late sends, sort claims by `(enrollment, step)`, steps hash on send rows, admin retry.
- **Mock chat provider in production is undetectable** (`chat/select.ts:15-16`, `launch-check.ts:59-60`).
  One launch-check rule + a boot log line + the kind in `/api/health`.
- **CSV hygiene** (`subscribers/export.csv`, `orders/export/+server.ts:27-42, 57-58, 89`): no BOM
  (mojibake in ro-RO Excel), formula injection via customer-entered names, whole-table scan then JS
  filter, no VAT-rate columns, `displayNumber` not escaped. XML/PDF lack an order/payment reference and
  mark a card-paid invoice payable (`PrepaidAmount`/means code 48, "Achitat cu cardul").
- **Consent cookie unversioned; cookie table names the wrong cookie on https**
  (`gdpr/consent.ts:11-14`, `cookies.ts:27` vs `__Secure-better-auth.session_token`).
- **Settings**: one DB blip 500s every public page (`(public)/+layout.server.ts:21`); IBAN not mod-97

- **Audit trail** covers orders and settings only — who exported subscribers, deleted media, toggled

- **Admin stock edit is an absolute write** racing the webhook decrement (`shop/service.ts:117-144`);

## Verified strong (so the picture is fair)

- Event ledger: claim-by-insert inside the effect's transaction; concurrent deliveries of one event
  block on the PK and the loser sees the committed outcome; a throwing effect rolls back everything.
- Gapless invoice numbering under a row lock, `issuedAt` computed after allocation, append-only
  enforced by `BEFORE UPDATE OR DELETE` triggers; storno lines negate stored amounts (rate-change proof);
  integer half-up VAT per line within BR-CO-17 tolerance.
- Shipping cost locked server-side, passed as the session's single fixed rate, invoiced as its own VAT
  line so `gross == amount_total`.
- Rate limiting is one atomic upsert with in-SQL window rollover; cron auth fails closed (503) with a
  length-guarded `timingSafeEqual`; chat session tokens are HMAC + DB-side anonymous-token check.
- Nurture claim is `FOR UPDATE SKIP LOCKED` + `UPDATE … RETURNING`, stale-claim recovery, consent
  re-checked at send time; DST math verified across both 2026 transitions.
- Every `db.transaction` callback uses only `tx` — correct for the 1-connection Neon pool; no
  warm-process state anywhere in the request path.
- Presign binds content-type and length; confirm re-derives mime/size/dimensions; ticket is HMAC +
  expiry; bundle types are compile-derived from the schema and round-trip `blurhash`/`gallery`.
- Sanitizer allowlists, JSON-LD escaping, consent-gated analytics that provably loads nothing before
  consent, transactional erase with fault injection, settings client boundary asserted on the
  serialized payload, no `any`, clean Svelte 5 runes throughout.
- Migrations: 20/20/20 journal↔files↔snapshots, additive only, defaults on every NOT NULL, unique
  claims wherever a retry can arrive.
